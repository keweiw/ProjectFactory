# M1 — Mobile Web MVP

**Status:** Complete
**Completed:** 2026-08-16
**Revised:** 2026-08-17

## What was built

- Mobile-first static web app in `index.html`, `style.css`, and `src/app.ts`.
- Home screen with a lifetime hit-rate summary from `localStorage`.
- Ten-question rounds loaded from the M0 content package at `../tickread/code/data/`.
- Setup-only candlestick chart before an answer; upward swipe/button means bullish and downward swipe/button means bearish.
- Locked answer flow: future bars animate in, then the result shows correctness, move, ticker, timeframe, date range, and response time.
- Next-question control is enabled after the required 2.2-second reveal period.
- Round report includes hit rate, longest streak, and all ten outcomes.

## Contract and privacy behaviour

The question screen reads only public metadata and setup bars before the user submits a direction. It reads answer and reveal fields only inside the locked answer/reveal flow. Each submitted response is stored locally as a `SessionRecord`-compatible object.

## Post-review fixes (2026-08-17)

Four issues were identified during code review and corrected before the M1 commit was pushed.

### 1. Reveal-field access in `isQuestion()` — contract violation

**Problem:** The original `isQuestion()` type guard checked `q.answer === "up" || q.answer === "down"` and iterated `q.future` to validate bar shape. Both are reveal-only fields. This check runs at load time, before the user sees any question, which technically violates the CONTRACT.md rule: *"must not be accessed before `given` is recorded."*

**Fix:** `isQuestion()` now validates only public fields (`id`, `assetClass`, `timeframe`, `horizon`, `setup`). It does not read `future`, `answer`, `symbol`, `startTime`, or `endTime` at load time. M0 validates the full content package before it ships; the app first reads reveal-only fields inside the locked post-answer flow.

### 2. `module: "node16"` in tsconfig — wrong target

**Problem:** `"module": "node16"` is a Node.js ESM mode. The app targets browsers served as `<script type="module">` with no bundler step.

**Fix:** Changed to `"module": "ESNext"` and `"moduleResolution": "bundler"` (correct for browser ES modules with TypeScript ≥ 5.0).

### 3. `Record` type name shadowed the TypeScript global utility type

**Problem:** `type Record = { ... }` overwrites the global `Record<K, V>` utility type for the entire file.

**Fix:** Renamed to `SessionRecord` throughout, matching the name used in CONTRACT.md and `session-record.schema.json`.

### 4. Biased shuffle

**Problem:** `pool.sort(() => Math.random() - .5)` produces a biased shuffle because the comparison function is not a consistent total order.

**Fix:** Replaced with a Fisher-Yates in-place shuffle before slicing to `ROUND_SIZE`.
