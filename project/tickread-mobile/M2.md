# M2 — History & Cumulative Report

**Status:** Complete
**Completed:** 2026-08-17
**Revised:** 2026-08-18

## What was built

- A History screen added as an independent M2 browser module, preserving the M1 game state machine.
- Lifetime hit rate, answer count, and current streak on the home screen.
- Cumulative hit-rate sparkline and overall report.
- Asset class, timeframe, and horizon breakdowns only after 20 records per group.
- Bullish-call bias and average response time only after 30 records.
- Local JSON export, validated JSON import, and confirmation-gated history clearing.

## Data and privacy

M2 reads only locally stored `SessionRecord` data plus public question metadata (`id`, asset class, timeframe, horizon) to group historical results. It never uses reveal-only fields for report grouping.

## Post-review fixes (2026-08-18)

Four issues were identified during code review and corrected.

### 1. Streak regression on home screen

**Problem:** `app.ts`'s `updateLifetime()` is called after every round (`showReport()`). It writes `#lifetime` without the streak, overwriting M2's richer stat line and dropping the streak each time the user finishes a round.

**Fix:** M2 now owns the `#lifetime` stat line. An `updateHomeStat()` function writes "X% lifetime hit rate · Y calls · streak Z". A `MutationObserver` watches `#lifetime` for changes and immediately re-applies `updateHomeStat()` whenever app.ts overwrites it. No changes to app.ts required.

### 2. Import overwrites history without confirmation

**Problem:** Importing a valid JSON file silently replaced the entire stored history with no warning.

**Fix:** A `window.confirm()` prompt now asks "Replace your current history with N imported records?" before writing to `localStorage`. The import is cancelled if the user declines. The meta cache is also busted on import so re-imported question IDs are re-resolved.

### 3. Blank sparkline for 1 record

**Problem:** With exactly one record, `moveTo` is called but no `lineTo` follows, leaving the canvas blank.

**Fix:** Single-record case is now handled separately — a filled circle is drawn at the canvas centre instead.

### 4. `questionMeta()` re-fetched all shards on every History open

**Problem:** All four shard files were re-fetched and parsed into a Map every time the user opened the History screen.

**Fix:** A module-level `metaCache` variable holds the result after the first successful fetch. Subsequent calls return the cached map immediately. The cache is cleared on history import (since new question IDs may need resolving).
